# Architecture

## Current status

The application uses a self-managed modular-monolith direction. Phase 1 adds a
React and TanStack Start application, TanStack Router, TypeScript, Tailwind CSS,
environment validation, and the PostgreSQL/Drizzle foundation. There are no
commerce modules or external provider integrations yet.

## Runtime shape

- Vite builds the TanStack Start application; `srvx` serves the generated
  fetch handler and client assets on Node.js.
- React renders the application and TanStack Router owns file-based routes.
- Server-side database code is kept under `src/server/` and uses `.server.ts`
  filenames.
- Drizzle ORM and the `postgres` driver provide PostgreSQL access.
- The database is a local Docker Compose service for development.

Client-facing modules must not import `src/config/env.server.ts`,
`src/server/`, database drivers, or server credentials. Public runtime settings
are parsed separately from the explicit `VITE_PUBLIC_*` allowlist.

## Current directory boundaries

| Path             | Responsibility                                                     |
| ---------------- | ------------------------------------------------------------------ |
| `src/routes/`    | TanStack Start route tree and HTML document                        |
| `src/config/`    | Server and public environment schemas                              |
| `src/server/db/` | PostgreSQL connection, health verification, and schema entry point |
| `src/lib/`       | Client-safe shared utilities                                       |
| `src/styles.css` | Dark editorial tokens and global styles                            |
| `scripts/`       | Local developer commands                                           |
| `tests/`         | Unit tests                                                         |
| `drizzle/`       | Version-controlled SQL migrations generated by Drizzle Kit         |

As the project grows, organize domain logic into focused modules (catalog,
inventory, orders, payments, shipping, and administration) without splitting
the application into microservices.

## Approved integrations and deferred work

Razorpay and Shiprocket are approved for later phases, but are not installed or
implemented in Phase 1. Authentication, storefront, commerce schema, Oracle,
email, and production deployment are also deferred.

## Design foundation

Global CSS variables define dark background, foreground, surface, border,
muted, accent, radius, and replaceable font-family tokens. Tailwind CSS 4 uses
these tokens through its CSS-first theme. The shadcn/ui configuration and
class-merging helper establish conventions. The foundation page uses a
responsive `object-fit: contain` image of the owner-supplied official AURYTH logo.
Its image asset is preserved as supplied. No shadcn primitives are included yet.
